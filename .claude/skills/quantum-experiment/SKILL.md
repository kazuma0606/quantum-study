# 量子実験の手順

## 0. 着手前

- `docs/research_ideas.md` に、テーマのカード（問い・やること・最初の一歩）があるか確認する。なければ作る。
- 先行研究を確認する（必要なら `literature-scout` サブエージェント）。「自分が付け加えられるもの」を1行で書く。
- 実験用のノートブックは `notebooks/research/<テーマ番号>_<名前>/` に置き、`notebook-gen` Skill に従って生成スクリプトから作る。

## 1. 理論とシミュレータが先

1. 期待される結果を、式（または小さな数値計算）で予測する。
2. Qiskit の AerSimulator で、雑音なし → 雑音モデルあり（`NoiseModel`、雑音の強さを変える）の順に確かめる。予測と合うことを `assert` で確認する。
3. 1量子ビットの回転の積は、トランスパイラが1つのゲートにまとめてしまうので、雑音の積み重なりを見たい実験では、CNOT などの2量子ビットゲートを含む回路にする。

## 2. 実機に投げる前の確認（必ずユーザーに見せて承認をもらう）

- **IBM Quantum（Open Plan）**：実機の利用は 28日あたり 10分。回路の数 × ショット数から、使う時間を見積もって伝える。トークンはユーザーが自分で設定する（会話やファイルに書かない）。
- **AWS Braket**：実機は「タスク1回 ＋ ショット1回ごと」の従量課金。実行前に、料金ページで単価を確認し、総額を見積もり、**コンソールで利用上限（スペンディングリミット）と AWS Budgets のアラートが設定されているか**をユーザーに確認してもらう。ノートブックのインスタンスは起動中ずっと課金されるので、使い終わったら停止するよう伝える。
- 最初は回路の数とショット数を最小限にして、1回だけ走らせ、結果の形を確かめてから本番にする。

## 3. 記録（再現性）

結果と一緒に、次を必ず残す（ノートブックの中の記録用セルと、`results/` の JSON など）：

- 実機の名前（バックエンド名）、日時（UTC と日本時間）、ショット数、乱数の種
- トランスパイル後の回路の深さ・CNOT の数、使った量子ビットの番号
- 実機の較正データ（その時点の CNOT の誤差、T1・T2、読み出しの誤差）
- Qiskit などのライブラリの版

## 4. まとめ

- シミュレータ（雑音なし・あり）と実機の結果を同じ図に重ね、予測との差と、その理由（雑音の種類）を書く。
- 結果は `docs/research_ideas.md` のカードに書き足し、次の一歩を更新する。
- 医療画像のテーマでは、患者のデータは使わない（公開ファントムか数値ファントムだけ）。
