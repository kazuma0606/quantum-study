# 研究ノートの書き方の方針（説明の粒度）

> **作成** 2026-10-20　**更新** 2026-10-26
> 研究ノートで「どこまで詳しく説明するか」の方針。予備知識の線引き、導出の書き方、書いたあとの検査の流れ、検査役のエージェントの分担をまとめる。

ノートの目的は、教科書や論文の式を天下りに受け取らず、導出し、コードで検算し、初めて読む人が鉛筆で追えるようにすることです。この文書は、`research-note` スキルと検査用のエージェントが従う基準です。

## 1. 予備知識の線引き：「導出済み」の扱い

初めて読む人が前提にしてよいのは、次のどれかに当てはまる概念だけです。

1. **このリポジトリのどこかのノートで、詳しい手順つきで導出されている**（タイトルになっているものを含む）。→ 導出し直さず、「○○ノートで導出済み」とリンクして使ってよい。
2. **頻出する基本語**（行列の積、転置、複素共役、トレースの定義など）。→ 初めて使うときに1行で意味を述べれば足りる。
3. 上のどちらでもないものは、**このリポジトリで初めて出る概念**として扱い、**詳解する**（定義、記号の意味、なぜそうなるかの導出、小さい数値例）。

どの概念がどこで導出済みかは、`docs/concepts.md` の表で管理します。

- 書く前に、使う概念が表にあるかを確かめる。ある → リンクで済ませる。ない → 詳解して、**同じコミットで表に追加する**。
- 表に載せる基準：ノートのタイトルになっている、詳細なステップで導出されている、複数のノートで頻出する、のどれか。

## 2. 導出の書き方（書く前に毎回確かめる5点）

1. **初めて出る記号・用語は、使う直前に、意味と型（ベクトルか行列か、大きさ）を1行で述べる。** 和の範囲、添字の範囲も含める。
2. **等号1つごとに、使った規則を書く。** 「同様に」「容易に」「明らか」「計算すると」で飛ばさない。
3. **抽象的な式の直後に、2×2 など小さい具体例を、数値で最後まで追えるように置く。** 数値は NumPy などで確かめる。
4. **主張を先に述べ**（箱で囲んだ式）、次に証明の方針、最後に番号つきの手順を書く。前提にする知識（外積、トレースなど）は、1行で復習する。
5. **書いたあとで、初学者として鉛筆で1回追う。** 追えない所は、省いた規則や記号の説明を足す。

加えて：

- **導入するもの・主張するものには、「なぜ必要か」「どうしてそう考えるか」「その根拠」を、文章の流れの中で、簡潔に述べる**：新しい量・定義・変形・結論を出すとき、この3点が読み手に伝わるように書く。ただし、**「動機」「発想」「根拠」などを見出しや項目名として並べない**（冗長になり、「何の根拠か」が分からなくなる）。1つの自然な文章の流れの中で、必要な理由を、必要な箇所に、短く書く。結論だけを先に述べて、理由を後ろで述べたり、省いたりしない。断定は、根拠が及ぶ範囲に限る（例：「行列が必要」と言うなら、ケットで足りる場合との区別を書く）。
- **説明の順序：前提条件 → 式の提示 → 説明**：その節で使う前提（記号、基底、階数などの復習）を先に置き、次に式を（別行で）示し、そのあとで説明する。「復習は下にあります」「後で説明します」と先送りして、式を先に出さない。使う前に、前提が済んでいること。具体例も同じ順（設定の式 → 計算の式 → 説明）で、1文に式を詰め込まない。
- **宣言を先に**：空間・ベクトル・演算子・次元の宣言と次元の表を、使う前に置く。
- **記法は、書く前に、既存に合わせる**：ノート冒頭の記号一覧と、すでに書かれた本文の記法（複素共役は `^\ast`、ノルム、基底の添字など）を、書く前に確かめて、同じ書き方にする。あとから統一する作業を、ユーザーに頼ませない。`tools/lint_notes.py` が、複素共役の記法の混在を報告する。
- **量子力学の用語は、教科書の言い方にする**：状態を表すベクトルは「状態ベクトル」（ケット $|\psi\rangle$ はその書き方）、状態ベクトルで記述できる状態は「純粋状態」、できない状態は「混合状態」。「1つのケットで書ける」のような、記号の個数に見える言い方をしない（$(|0\rangle+|1\rangle)/\sqrt2=|+\rangle$ のように、書き方で個数が変わる）。ケットは、ブラと組み合わせて確率（内積）や密度行列（外積）を作る記法。
- **用語を統一する**：同じものに、同じ言葉を使う（例：ノルムを「長さ」と呼んだり、「ノルム」と呼んだりしない）。別の言葉を使うなら、初めに「ノルム（長さ）」のように対応を1回だけ書き、あとは1つに決める。記号も同様（同じ量に別の記号を使わない）。
- **先取りしない**：読む順（Part、付録A→B→C）で後ろにあるものを、前で使わない。使うなら、前で証明してから使う。
- **先取り・後出し・結果の先出しは、例外なく不可**：定義や前提を使った後で説明しない。「次の式が得られます」と結果を先に置いて、根拠を後ろに回さない。式は導出の順（代入 → 計算 → 結果）に1つずつ示す。ケットとブラの積のような対象も、最初に与えず、必要になる計算（たとえば期待値）から自然に現れる形で導入する。自分の勉強のためのノートなので、途中を省いたり簡易的に済ませたりしない。順序を崩す必要が出たら、崩す前に相談する。
- **式は別行に**：文中に式を埋め込まず、別行の数式で目立たせる。
- **端点を確かめる**：「〜でない」「必ず〜」「常に〜」と書くときは、パラメータの端（ε = 0, 1、θ = 0, π、次元 1、係数 0 など）で成り立つかを確かめ、成り立つ範囲を明記する。

## 3. 頼まれた範囲だけ直す

1つの式の展開を頼まれたら、その式の導出だけを丁寧にし、前段や他の節を書き換えない。構成の大きな変更や、他のノートへの波及は、先に方針を示して確認する。

**読み手は、ノートを手書きで書き写しながら読む。** そのため、次を守る。

- **書き写された（と言われた）式・文は、動かさない。** 順序、記号、言い回しを変えない。足したい内容は、その**後ろ**に置く。
- **頼まれていない記号（チルダなど）や定義を、勝手に作らない。** 既存の記号と式で表す。新しい記号が要ると思ったら、書く前に、候補を示して確認する。
- **ノートの本文を書き換える前に、修正の方向を示し、承認を得てから書き換える。** 示す内容は、(1) どの文・式の**後ろ**に、(2) 何を（式なら式そのもの）、(3) どの順で足す・変えるか、(4) 動かさない部分。承認なしで行ってよい例外は、ヘッダーの更新日と、元に戻す操作の2つだけで、条件は `.claude/skills/research-note/SKILL.md` の「承認が要る編集と、要らない編集」に従う（誤字や書式の修正も、先に示す）。いきなり書き換えると、意図とずれた文章になり、直す往復が増える。
  案を出す前の確認は、`.claude/skills/research-note/SKILL.md` の「案を出す前の関門」に従う。
- **指示が曖昧なときは、推測で書き換えない。** 候補を示して、どれにするかを先に確かめる。
- 直したあとは、変更した範囲（どの文・式を、どこに足したか）を、そのまま報告する。

## 4. 書いたあとの流れ

1. **書く**（`research-note` スキル）。数式は先に NumPy・SymPy で検証する。
2. **機械的な検査**：`tools/lint_notes.py`（飛ばし表現、式の埋没、先取りの参照）、`tools/scan_bars.py`、`tools/linkcheck.py`、目次の確認。
3. **説明の粒度の監査**：`granularity-reviewer`（初学者の目で、飛躍と未定義を探す）。
4. **数式・論理の監査**：`math-auditor`（式を再計算し、端点・次元・量化を確かめる）。
5. 指摘を直し、テストを通し、日付の見出しをそろえてコミットする。

監査役は、ノート1本、または大きな改訂ごとに走らせる（1回に数分かかる）。細かい直しのたびには走らせない。監査役はファイルを編集せず、報告だけする。
