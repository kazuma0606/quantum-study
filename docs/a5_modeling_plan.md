# A-5 実験計画：雑音のモデリング（2026年10月〜）

テーマ A-5 の次の段階の計画です。実機で見つかった雑音（CNOT ごとのコヒーレントな回転、組ごとの違い、ジョブごとの揺らぎ）を、**ベイズの階層モデル**として表し、推定のしかた（サンプリング、変分推論、ニューラルネットによる推論）と機械学習の基準手法を、同じ物差しで比べます。議論の経緯は [a5_discussion_noise_modeling.md](a5_discussion_noise_modeling.md)、これまでの結果は [experiments/a5_trotter_noise/README.md](../experiments/a5_trotter_noise/README.md) にあります。

## 1. 目的と問い

- **目的**：実機の $\langle Z_0\rangle$ のずれを、トロッター誤差・コヒーレントな誤差・確率的な誤差・ジョブごとの揺らぎ・組ごとの違い・ショットのばらつきに、**不確かさつきで分けて推定する**。
- **問い**
  1. 1つの構造（共通の形＋組ごとの値＋ジョブごとの揺らぎ）で、2組・2日分のデータを同時に説明できるか。
  2. どの誤差の形がデータに支持されるか（人が選ぶ代わりに、データに選ばせられるか）。
  3. ジョブごとの揺らぎは、時間の滑らかな変化と、まれな跳びに分けられるか。跳びは較正の値（T2 など）と関係するか。
  4. 推定のしかた（NUTS、SVI、SBI）で、答えと不確かさの正直さはどう違うか。
  5. 機械学習の基準手法（ランダムフォレスト、XGBoost）と比べて、物理を入れたモデルは「学習していない条件」でどれだけ良いか。
  6. 来月の実機の 10 分で、何を測れば成分を一番よく分けられるか。

## 2. 正解と報告の約束（分野の慣習に合わせる）

- 3つの値を並べる：正確な値 $e^{-iHt}$、雑音なしのトロッター回路の値（誤差緩和の正解）、実測の値。
- 差は**符号つき**で残す：実機の誤差＝実測−雑音なしの回路、トロッター誤差＝雑音なしの回路−正確な値。
- 推定値には不確かさ（事後分布の区間）を付ける。比較には、許容範囲を先に決めた同等性の考え方を使う。

## 4. モデル

### 4-1. 共通の前向き計算（すべてのモデルの土台）

回路（RX、CX・RZ・CX）を密度行列で計算し、各 CNOT の直後に誤差を入れる。JAX で書き、自動微分できるようにする（NUTS・SVI・SBI の共通の部品）。ツイリングありのデータでは、同じコヒーレントな誤差をパウリ通路に置き換える。直接の測定の回路（CNOT の組だけ）と、監視用の回路も、同じ部品で計算する。

### 4-2. 誤差の形の候補（最初にいろいろ変えて比べる）

| 名前 | CNOT の直後の誤差 |
|---|---|
| F1：Z 位相 | $Z_c, Z_t$ の回転＋脱分極 |
| F2：CZ 型 | $Z_c, X_t, Z_cX_t$ の回転＋脱分極（これまでの当てはめで最も良かった） |
| F3：一般 5 項 | $Z_c, Z_t, X_t, Z_cX_t, Z_cZ_t$ の回転＋脱分極 |
| F4：疎な 15 項 | 2量子ビットのパウリ 15 項すべての回転に「ほとんどは 0 に近い」事前分布（ホースシュー事前分布など）を置き、要る項をデータに選ばせる |
| F5：物理寄り（後回し） | 常にかかる ZZ の結合（待ち時間や1量子ビットゲートの間も効く）、周波数のずれなど、ゲートの仕組みに由来する少数のパラメータ |
| F6：確率的な部分の一般化（後回し） | 脱分極の代わりに、パウリごとに違う確率（IBM の疎なパウリ・リンドブラッド模型の考え方） |

### 4-3. 階層（組ごとの値）

回転の角度と脱分極の強さは、組ごとに違う値を持ち、それらが共通の分布から出ていると置く（組ごとの平均・ばらつきも推定する）。脱分極の強さの事前分布は、較正の CZ 誤差のまわりに置く。

### 4-4. ジョブごとの揺らぎの候補

| 名前 | 中身 |
|---|---|
| D0：なし | 揺らぎを入れない（基準） |
| D1：裾の重い分布 | ジョブごとのずれ ～ スチューデントの t 分布 |
| D2：混合（切り替え） | 各ジョブは「ふだん」か「跳んだ」かのどちらか。跳ぶ確率も推定する |
| D3：ガウス過程＋跳び | 時間の滑らかな変化をガウス過程（数分〜数時間と、日をまたぐ、2つの時間スケール）で、急な跳びを混合で表す |
| D4：説明変数つき | ずれの一部を、その日の較正の値（量子ビット 22 の T2 など）で説明する。「T2 の低い日に跳びやすいか」を検定できる |

揺らぎを入れる項は、直接の測定で時間とともに動いていた制御の Z 位相を第一の候補にし、他の項に入れた版とも比べる。

### 4-5. 機械学習の基準手法

物理モデルの残差（実測−物理モデルの予測）を、表形式の特徴量（$n$、次数、ツイリングの有無、組、時刻、その日の較正の値）から学ぶ。

- ランダムフォレスト（バギング。IBM の ML 誤差緩和の論文でも比較対象）
- XGBoost（ブースティング。残差を順に学ぶ点で「物理＋残差」と同じ発想）

決定木の手法は学習した範囲の外へ外挿できず、そのままでは不確かさも出ないので、その限界も評価の対象にする。

## 5. 推定のしかた

| 方法 | 役割 | 道具 |
|---|---|---|
| NUTS（サンプリング） | 正確な事後分布。**ほかの方法を比べる物差し** | NumPyro（CPU） |
| SVI（変分推論） | 速い近似。見えない状態の推定を NN にさせると VAE になる | NumPyro、のちに PyTorch |
| SBI（シミュレーションに基づく推論） | 合成データから「データ → 事後分布」を NN が直接学ぶ。学習後は一瞬で推定できる | PyTorch（GPU）、`sbi` |

推定が正しいかは、**シミュレーションに基づく較正（SBC、Talts ら 2018）**で確かめる。正解のパラメータから合成データを作って推定し、「68% の区間に正解が 68% の確率で入るか」をくり返し確かめる。

## 6. 評価の物差し（すべてのモデルと方法に共通）

| 物差し | 中身 |
|---|---|
| 1ジョブ抜きの交差検証 | 1本のジョブを抜いて学習し、そのジョブを予測する（揺らぎを予測できるか） |
| 1組抜きの交差検証 | 22–23 で学んで 142–143 を予測する、とその逆（学習していない条件への強さ。医療画像の「別のデータセットでの評価」に当たる） |
| モデルの比べ方 | PSIS-LOO（1点抜きの交差検証の近似、ArviZ）と、それによるスタッキング（予測の良さで重みづけしてモデルを混ぜる） |
| 事後予測の確認 | モデルから作ったデータが、実データと矛盾しないか |
| 不確かさの正直さ | SBC、正解の分かる実データでの区間の当たり率 |
| 判断のレベル | 推定した値で選んだ $n$ の**後悔**と、**判断の余裕**（判断が変わらない誤差の範囲） |
| 個別の確認 | 19:49 の跳んだジョブを「跳んだ」と見抜けるか。直接の測定の値（当てはめのずれがあった制御の Z 位相）と合うか |
| 収束の確認（ベイズ） | R-hat、有効サンプル数、発散の有無 |

## 7. 段階と、次へ進む条件

各段階で一番良かったものを残して先へ進む（全部の組み合わせは試さない）。

| 段階 | やること | 次へ進む条件・成果物 |
|---|---|---|
| S1 | 共通の前向き計算（JAX）と、正解が分かる合成データの生成器 | これまでの NumPy の計算と数値が一致する（テストで固定） |
| S2 | 誤差の形 F1〜F4 を NUTS で当てはめる（揺らぎは D0・D1）。まず合成データで正解を取り戻せるか、次に実データ | 合成データで正解を区間内に取り戻せる。実データで形を LOO とスタッキングで比べる |
| S3 | 揺らぎ D2〜D4 を加える | 1ジョブ抜きの予測、19:49 のジョブの検出、跳ぶ確率と T2 の関係 |
| S4 | SVI と SBI を NUTS と比べる（SBC を含む） | 答えの一致、不確かさの正直さ、速さの比較 |
| S5 | 機械学習の基準手法と、同じ交差検証で比べる | 1組抜きでの差、外挿できない限界の確認 |
| S6 | 合成データで、来月の測り方を選ぶ（$n$ の組み合わせ、ツイリング、雑音の倍率 1 倍・3 倍、監視用の回路、ショット数を、月 10 分の枠内で） | 来月の測定の設計と、測る前に書く予測 |

実機の時間は S1〜S6 では使わない。来月の測定（S6 で選んだもの）は、時間の見積もりと承認を得てから行う。

## 8. 環境

- PC：NVIDIA GeForce RTX 5070 Ti（16 GB）、Python 3.12（uv）。
- 追加済み：NumPyro 0.22、JAX 0.11（CPU 版）、ArviZ 1.3。Windows の JAX は GPU を使えないので、ベイズの推定は CPU で行う（モデルは小さいので十分）。
- NN を始めるとき（S4）に、PyTorch（RTX 50 系に合う CUDA 12.8 以降の版）と `sbi` を追加する。XGBoost は S5 で追加する。

## 10. 分かっている注意点

- 実データは少ない（数百点、組は 2 つ、日は 2 日）。組ごとのばらつきの推定は、組が 2 つしかないので不確かさが大きい。
- 合成データは今の仮定で作るので、仮定の誤りも学ぶ。物理モデルで説明しきれない残差を、いつも明示的に見る。
- どんな手法でも、偏りを消す代わりに必要な測定の数が増える（誤差緩和の根本的な限界）。目標は「限界の手前で、少ない測定で、正直な不確かさつきで推定すること」。
